# Execution desk requirements

1. Load original and repaired recorded parent/child JSON using the same auditor. Original is mismatch (two items), repaired is consistent (zero mismatches); both recorded executions are successful.
2. Every finding can show the path actually traversed from child terminal output to its input boundary, preserving node/run/output/item, original pairedItem entry, selected source and producer run/output. Every displayed JSON pointer resolves in the original file; initial terminal output is real, never internal -1.
3. A parent-first import extracts actual metadata.subExecution.executionId and gives the child download command. Two complete API execution JSON files are locally parsed, paired by recorded metadata and audited. Definition-only exports and missing raw return incomplete with exact actionable location/contract. No API keys are collected.
4. Download a compact structural report. Business JSON is excluded. Custom imported records get ancestry findings; the separately recorded demo HTTP observations never carry over.
5. One memorable, selectable switchboard represents parent recorded vs child resolved ancestry. Keyboard operation, narrow layout and readable states are part of the complete product.
6. Kiro uses this spec and steering to perform real implementation; an evidence-check Hook runs the minimal fixtures and raw-pointer check. Public open-source repo contains /.kiro, and an English public YouTube video under 3 minutes shows the actual app and Kiro work.
